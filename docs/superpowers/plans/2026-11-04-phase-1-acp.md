# Giai đoạn 1 — Một agent chạy trọn vẹn: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Giao một task sửa code cho agent → duyệt lệnh → xem diff → accept từng hunk → commit, không rời app.

**Architecture:** Mỗi run có một git worktree riêng và một tiến trình adapter ACP. `acp/transport.rs` lo JSON-RPC, `acp/client.rs` lo vòng đời phiên, `acp/handlers.rs` phục vụ fs/terminal trong worktree. `diff.rs` đánh dấu hunk đã accept bằng index của worktree, nên hàng chờ chính là `git diff` trong worktree.

**Tech Stack:** Rust + tokio, git CLI, ACP v1 (`protocolVersion: 1`), Angular 22 signals, Monaco.

**Spec:** `docs/02-roadmap.md` (GĐ1), `docs/03-agent-integration.md`, `docs/06-design-system.md`.

## Global Constraints

- Tuân theo `AGENTS.md`. Mọi tiến trình con dùng `env::login_path()`; đường dẫn truyền bằng argument, không nối chuỗi shell.
- Không thêm crate mới nếu chưa có trong plan. Codex build bằng `cargo --offline`, không commit.
- Thông báo lỗi cho người dùng viết tiếng Việt.
- Agent không được ghi ngoài worktree; `git push`/merge luôn bị từ chối (`03` §5).
- Phiên bản adapter được ghim: `@agentclientprotocol/claude-agent-acp@0.100.0`, `@zed-industries/codex-acp@0.16.0`.

## Review Focus

1. Thư mục không phải git repo hoặc repo chưa có commit: báo lỗi rõ, không tạo run dở (Task 2, Task 6).
2. Agent crash hoặc adapter không cài được giữa chừng: run thành `failed`, giữ log và worktree, mọi thẻ duyệt đang mở biến mất (Task 3, Task 6).
3. Lệnh ghép lách quyền: `npm test; rm -rf ~` không được khớp rule `npm test *` (Task 5).
4. Accept hunk khi người dùng đã sửa cùng đoạn đó: báo lỗi, không làm hỏng file nào (Task 2).
5. Đường dẫn có dấu cách, Unicode và file mới: xem diff, accept và reject đều đúng (Task 2).

### Task 2: `worktree.rs` + `diff.rs` (Owner: Codex)

**Files:** Create `src-tauri/src/worktree.rs`, `src-tauri/src/diff.rs`. Modify `src-tauri/src/lib.rs` (hai `#[allow(dead_code)] mod`).

**Interfaces — Produces** (tất cả `#[derive(Debug, Clone, PartialEq, Serialize)]`, `camelCase`; lỗi là `String` tiếng Việt):
```rust
// worktree.rs
pub struct Worktree { pub run_id: String, pub path: PathBuf, pub branch: String, pub base: String }
pub fn git(cwd: &Path, args: &[&str], stdin: Option<&[u8]>) -> Result<String, String>; // PATH = env::login_path(), core.quotepath=false, lỗi kèm stderr
pub fn slugify(title: &str) -> String;  // a-z0-9 và '-', gộp '-', tối đa 40 ký tự, rỗng → "task"
pub fn create(repo: &Path, agent: &str, title: &str, run_id: &str) -> Result<Worktree, String>;
pub fn list(repo: &Path) -> Result<Vec<Worktree>, String>; // chỉ worktree dưới .tg/worktrees
pub fn remove(repo: &Path, wt: &Worktree, delete_branch: bool) -> Result<(), String>;
// diff.rs
pub struct Hunk { pub id: String, pub header: String, pub old_start: u32, pub old_lines: u32, pub new_start: u32, pub new_lines: u32, pub lines: Vec<String>, pub added: u32, pub removed: u32 }
pub struct FileDiff { pub path: String, pub status: String /* M|A|D */, pub binary: bool, pub patch_header: String, pub hunks: Vec<Hunk> }
pub fn parse_unified(text: &str) -> Vec<FileDiff>;
pub fn pending(wt: &Worktree) -> Result<Vec<FileDiff>, String>;
pub fn accept_hunk(repo: &Path, wt: &Worktree, path: &str, hunk_id: &str) -> Result<(), String>;
pub fn reject_hunk(wt: &Worktree, path: &str, hunk_id: &str) -> Result<(), String>;
pub fn commit(repo: &Path, message: &str) -> Result<String, String>; // trả về hash; chỉ commit phần đã stage, không --no-verify
```
Quy ước:
- `create`: path `<repo>/.tg/worktrees/<run_id>`, nhánh `tg/<agent>/<slug>-<8 ký tự đầu run_id>`, base = HEAD; thêm `.tg/` vào `info/exclude` của common dir (không trùng lặp). Không phải repo hoặc chưa có commit → lỗi rõ.
- `pending`: nếu HEAD của worktree khác base (agent tự commit) thì `git reset --mixed <base>`; `git add -N .`; rồi `git diff --no-color --no-ext-diff --no-renames`. Vì so index với working tree, hunk đã accept (đã stage) tự rời hàng chờ.
- `id` của hunk: hash ổn định từ path + nội dung dòng, không phụ thuộc số dòng.
- `accept_hunk`: tìm lại hunk trong `pending`; `git apply --check --recount` trên repo người dùng và `--cached` trên worktree, cả hai qua rồi mới áp: `git apply --index --recount` vào repo, `git apply --cached --recount` vào worktree. Không tìm thấy id → lỗi. Binary → lỗi rõ.
- `reject_hunk`: `git apply -R --recount` trong worktree.

- [ ] **Step 1: Viết test** trên repo tạm (đặt `user.name`/`user.email` bằng `git -c` hoặc config repo tạm; không đụng config người dùng):

  - `create_makes_branch_and_excludes_tg`, `create_twice_keeps_one_exclude_line`, `create_rejects_non_repo_and_empty_repo`
  - `list_and_remove_round_trip`, `remove_keeps_branch_unless_asked`
  - `parse_quoted_and_unicode_paths`, `parse_new_deleted_and_binary`, `parse_no_newline_marker`
  - `accept_one_of_two_hunks_applies_only_that_hunk`: repo người dùng chỉ có hunk đó, `pending` còn đúng hunk kia
  - `reject_removes_hunk_from_worktree`
  - `new_file_accept_and_reject`, `deleted_file_accept`
  - `path_with_space_and_unicode_accepts`: `thư mục có dấu cách/tệp mới.txt`
  - `accept_conflict_leaves_both_sides_untouched`: người dùng đã sửa cùng dòng → lỗi; `git status` hai bên không đổi
  - `agent_commit_still_appears_in_pending`
